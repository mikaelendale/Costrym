# 🤖 Task Approval System Documentation

## Overview

The Task Approval System allows users to review and approve AI-generated tasks before they are executed. This provides users with full control over the cost-saving tasks generated by the MasterOrchestrator AI.

## Backend Architecture

### Controllers

#### `TaskApprovalController.php`

**Methods:**

1. **`approve(Request $request, Task $task)`**
   - Validates user ownership of task
   - Ensures task is in 'pending' status
   - Updates task status to 'approved'
   - Logs approval action
   - Returns success message
   - Ready for future integration with task execution system

2. **`reject(Request $request, Task $task)`**
   - Validates user ownership of task
   - Ensures task is in 'pending' status
   - Updates task status to 'cancelled'
   - Logs rejection action
   - Returns success message

3. **`index(Request $request)`**
   - Returns JSON list of pending tasks for authenticated user
   - Orders by priority and creation date
   - Used for API access to pending tasks

### Routes

```php
// In routes/web.php (auth middleware required)
Route::post('tasks/{task}/approve', [TaskApprovalController::class, 'approve'])
    ->name('tasks.approve');

Route::post('tasks/{task}/reject', [TaskApprovalController::class, 'reject'])
    ->name('tasks.reject');
```

### Database Schema

**Task Status Enum:**
- `pending` - Awaiting user approval (default)
- `approved` - Approved by user, ready for execution
- `running` - Currently being executed
- `completed` - Successfully completed
- `failed` - Execution failed
- `cancelled` - Rejected by user

**Key Columns:**
- `user_id` - Foreign key to users table
- `agent_name` - Which AI agent will execute this task
- `status` - Current task status (enum)
- `data` - JSON field containing:
  - `name` - Task name
  - `description` - Full task description
  - `task_type` - 'one_time' or 'looping'
  - `estimated_savings` - E.g., "$300/month"
  - `schedule` - Optional schedule info
  - `metadata` - Any additional data
- `priority` - Integer (1 = high, 2 = medium, 3 = low)
- `order` - For sequencing tasks
- `error_message` - Stored if task fails
- `started_at` - Timestamp when execution began
- `completed_at` - Timestamp when execution finished

## Integration with Dashboard

### `dashboard.tsx`

**Location:** `resources/js/Pages/dashboard.tsx`

The dashboard page:
1. Receives `pendingTasks` prop from backend
2. Imports `PendingTasksCard` component
3. Renders the card in the main content area
4. Passes tasks array to the component

**Backend Data Passing:**
```php
// In routes/web.php
Route::get('dashboard', function () {
    $pendingTasks = \App\Models\Task::where('user_id', auth()->id())
        ->where('status', 'pending')
        ->orderBy('priority')
        ->orderBy('created_at', 'desc')
        ->get();
    
    return Inertia::render('dashboard', [
        'pendingTasks' => $pendingTasks,
    ]);
})->name('dashboard');
```

## User Flow

### 1. Task Generation
- User completes onboarding
- MasterOrchestrator AI analyzes financial data
- AI generates cost-saving tasks
- Tasks saved with status = 'pending'

### 2. Task Display
- User navigates to dashboard
- PendingTasksCard component loads
- Displays count badge: "3 Awaiting Approval"
- Shows list of task cards

### 3. Task Review
- User clicks on a task card
- Modal opens with full task details
- User sees:
  - What the task will do
  - Which AI agent will execute it
  - Estimated savings
  - Schedule (if recurring)
  - Priority level

### 4. Task Decision
- **Approve:** User clicks "✓ Approve & Execute"
  - Status changes to 'approved'
  - Success message shown
  - Modal closes
  - Task removed from pending list
  - (Future: Task queued for execution)

- **Reject:** User clicks "Reject"
  - Status changes to 'cancelled'
  - Success message shown
  - Modal closes
  - Task removed from pending list
  - Task will not execute

### 5. Real-time Updates
- Inertia.js automatically refreshes data
- Pending tasks list updates
- Count badge updates
- No page reload required

## Security Features

### User Ownership Validation
- Every approval/rejection checks `task->user_id === auth()->id()`
- Returns 403 Forbidden if user doesn't own the task
- Prevents users from approving others' tasks

### Status Validation
- Only 'pending' tasks can be approved/rejected
- Prevents double-approval or modification of running tasks
- Returns error message if status is invalid

### Comprehensive Logging
```php
Log::info('Task approved by user', [
    'task_id' => $task->id,
    'user_id' => $request->user()->id,
    'task_name' => $task->data['name'] ?? 'Unknown',
]);
```

## Troubleshooting

### Issue: Tasks not appearing on dashboard
**Solution:** Check that tasks have `status = 'pending'` and belong to the authenticated user

### Issue: Approval/rejection not working
**Solution:** Verify routes are registered and CSRF token is being sent with Inertia requests

### Issue: Database constraint error on status update
**Solution:** Run migration to add 'approved' and 'cancelled' to status enum:
```bash
php artisan migrate
```

### Issue: Modal not opening
**Solution:** Check browser console for JavaScript errors, ensure React component is properly built
